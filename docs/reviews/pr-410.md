## Descrição e evidências da PR

## Problema

Projetos podiam concluir o jogo sem chegar a uma URL testável porque a continuidade da entrega dependia de JavaScript no navegador. Havia múltiplos mutadores concorrentes (jogo, auto-progress, cards desktop e mobile), enquanto o backend não iniciava uma entrega ainda em `pending` após o Gate 7/7.

## Correção

- adiciona `delivery_recovery_worker` durável;
- detecta a missão mais recente e inicia entrega quando o verificador da fase 7/7 conclui;
- continua `provisioning/deploying` e recupera `failed/blocked` com backoff persistido;
- executa recuperação em worker dedicado e embedded sem starvation por filas de tarefas/RAG;
- torna game gate, painel final, cards desktop e mobile observadores GET-only;
- remove `delivery-auto-progress.js` do bootstrap e o torna um stub sem mutação;
- mantém ações manuais como fallback;
- atualiza contratos para impedir reintrodução de deploy automático no browser.

## Contrato final

`Gate 7/7 -> worker -> clouds -> validação pública -> status=ready + URL HTTPS -> UI exibe URL`

Fechar/recarregar a aba não interrompe o fluxo.
