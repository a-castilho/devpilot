## Descrição e evidências da PR

## Problema
O Codex CLI pode encerrar tarefas de desenvolvimento com `You've hit your usage limit`, deixando o DevPilot com status genérico `failed`, Provider `—` e JSONL bruto. Conexões de IA cadastradas no AgentOS não substituem automaticamente a autenticação da sessão ChatGPT usada pelo executor Codex de escrita.

## Implementado
- classifica falhas Codex em `usage_limit`, `rate_limit`, `auth`, `transient` e `execution`;
- mantém ChatGPT/Codex como primeira tentativa;
- em limite/rate limit, faz no máximo uma tentativa alternativa usando uma conexão OpenAI salva no vault;
- fallback usa `CODEX_HOME` temporário e `auth.json` isolado com permissão `0600`, sem reutilizar tokens da sessão ChatGPT;
- API key não aparece em argumentos, logs ou frontend;
- fallback é cancelado se a primeira tentativa deixou alterações parciais na worktree;
- indisponibilidade externa vira `blocked`, não `failed`;
- run registra executor, provider, auth mode, tentativas, failure code e uso de fallback;
- endpoint `POST /api/tasks/{task_id}/retry` preserva a tarefa e o histórico ao recolocá-la na fila;
- dashboard exibe diagnóstico amigável, cadeia de tentativas, próxima ação, botão Reexecutar e atalho para Modelos de IA;
- configuração global para desligar o fallback ou reservar uma conexão OpenAI específica;
- testes de classificação, bloqueio, fallback isolado, não vazamento de segredo e proteção contra estado parcial;
- CI valida o novo JavaScript;
- documentação em `docs/codex-execution-recovery.md`.

## Limite intencional
Anthropic, Gemini e Ollama não assumem tarefas de escrita automaticamente. Eles permanecem no gateway AgentOS para análise/planejamento até existir um executor agentivo de escrita com as mesmas garantias de branch, comandos, testes e auditoria do Codex.

## Custo
O fallback OpenAI API é independente da franquia da sessão ChatGPT e **pode consumir créditos de API**. Pode ser desativado com `DEVPILOT_CODEX_API_FALLBACK_ENABLED=false`.
