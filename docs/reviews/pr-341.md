## Descrição e evidências da PR

## Objetivo
Fechar o P0 identificado na auditoria técnica: probes de URLs públicas de Vercel/Render usavam `follow_redirects=True`, permitindo que uma URL inicialmente aceita redirecionasse o backend para loopback, rede privada ou link-local.

## Mudanças
- adiciona `app.services.safe_http_probe` como política central de probes públicos;
- exige HTTPS e porta 443;
- rejeita userinfo na URL;
- mantém todos os hops em `*.vercel.app` ou `*.onrender.com`;
- resolve DNS antes de cada request e rejeita qualquer endereço não global;
- desativa redirects automáticos e proxies de ambiente;
- segue no máximo 3 redirects, validando cada destino antes do próximo request;
- aplica o helper em `delivery_url_recovery` e no `delivery_cloud_bridge` efetivo;
- endurece `_safe_public_url` para credenciais, porta e hostname canônico;
- adiciona testes para loopback, link-local, DNS privado, host externo, porta não padrão, redirect permitido e limite de hops;
- documenta a política em `docs/SECURITY_DELIVERY_PROBES.md`.

## Escopo
Chamadas de provisionamento para hosts fixos das APIs oficiais de Neon/Render/Vercel não são alteradas. O `verify()` efetivo do runtime é instalado pelo cloud bridge e passa pelo novo helper.
