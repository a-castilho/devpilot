## Descrição e evidências da PR

## Problema
Falhas antigas de clone/fetch com HTTP 401/403 apareciam na tabela como `FAILED` seguido do stderr bruto do Git, quebrando o layout e sem indicar a ação necessária.

## Implementação
- classifica falhas conhecidas de GitHub, Codex, rede, filesystem, banco e estado do checkout;
- converte erros GitHub 401/403 em mensagem curta e acionável para o usuário;
- mantém o stderr completo apenas nos detalhes técnicos;
- expõe `failure_category`, `failure_code` e `requires_authorization` no resumo da execução;
- preserva e prioriza o diagnóstico do self-healing quando disponível;
- adiciona testes para 403, mensagem de autocorreção e sanitização.

## Contexto
O fluxo de self-healing já faz failover seguro entre credenciais GitHub. Esta alteração fecha o gap de apresentação/diagnóstico, inclusive para execuções históricas que ainda possuem apenas stderr bruto.
