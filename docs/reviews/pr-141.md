## Descrição e evidências da PR

## Objetivo

Fecha o gap entre uma falha real do GitHub Actions e a fila/worker já existentes no DevPilot, sem reimplementar executor, autocorreção operacional, automação Git ou quality gates.

## Revisão da análise anterior

Durante a auditoria do `main` foi confirmado que o gate E2E real do Modo Jogo em Playwright/Chromium **já está implementado** e integrado ao job `DevPilot full quality`. Esta PR não duplica essa capacidade.

## Implementação

- receiver `POST /api/integrations/github/webhook` separado das rotas de sessão;
- validação obrigatória de `X-Hub-Signature-256` com HMAC SHA-256;
- processamento somente de `workflow_run: completed` com `failure`/`timed_out`;
- resolução do projeto por repositório já cadastrado no DevPilot;
- fingerprint determinístico para idempotência/redelivery;
- `Task(source=ci-recovery, priority=100, requires_approval=false)` para o worker existente;
- circuit breaker: máximo de 3 recuperações por branch em 6 horas;
- eventos de auditoria `ci.recovery.queued` e `ci.recovery.circuit_open`;
- configuração `DEVPILOT_GITHUB_WEBHOOK_SECRET`;
- testes de parsing, fingerprint/rerun e assinatura HMAC;
- documentação arquitetural em `docs/ci-failure-orchestrator.md`.

## Regra de segurança

A task de recuperação proíbe explicitamente desabilitar/ignorar/enfraquecer testes para obter verde e exige `bash scripts/test-all.sh` antes de concluir. O GitHub Actions continua sendo a fonte oficial do gate.
