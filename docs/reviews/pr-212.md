## Descrição e evidências da PR

## Problema
O `/api/chat` já injeta `build_chat_knowledge_context`, mas o runtime Docker não habilitava `DEVPILOT_RAG_ENABLED` e não executava `app.rag_worker_entry`. Na prática, o chat podia estar integrado ao RAG no código sem recuperar chunks indexados.

## Mudança
- habilita RAG explicitamente no serviço `app` do Docker Compose;
- adiciona um único `rag-worker` para consumir jobs de indexação, preservando o requisito low-RAM;
- mantém PostgreSQL/pgvector + Redis já existentes;
- adiciona testes de regressão para o wiring do chat/RAG.

## Segurança / isolamento
Nenhum segredo foi adicionado. O retrieval existente continua isolado por `organization_id` e `project_id` e permanece fail-open quando o backend RAG está indisponível.
