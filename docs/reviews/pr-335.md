## Descrição e evidências da PR

## Problema
O gate `DevPilot policy` está falhando em `main` porque `app/static/feature-loader.js` ainda contém `requestIdleCallback` para iniciar uma segunda onda automática de `projectBuilderEnhancements` depois que o bundle crítico do Novo projeto termina de carregar.

Esse bloqueio é global: qualquer PR passa a falhar antes de chegar aos testes, inclusive a correção de GitHub `description` da PR #334.

## Correção
- remove o disparo automático de `scheduleProjectBuilderEnhancements()` após `projectBuilder`;
- elimina `requestIdleCallback` do `feature-loader.js`;
- mantém o bundle opcional disponível, mas sem segunda onda automática;
- corrige o teste legado para refletir o contrato atual do bundle crítico do Novo projeto, no qual `project-provisioning.js` não entra no clique do builder simples;
- documenta a causa e a validação esperada em `docs/reviews/pr-frontend-policy-idle-second-wave.md`.

## Escopo
Alteração mínima e separada da PR #334. Não altera backend, banco, GitHub provisioning, credenciais ou infraestrutura.

## Validação
Esperado no CI:
- `DevPilot policy` verde;
- `node --check app/static/feature-loader.js`;
- testes de contrato do builder e runtime sem `requestIdleCallback`.

Depois desta correção entrar em `main`, a PR #334 deve ser atualizada/revalidada para que seus testes completos possam executar.
