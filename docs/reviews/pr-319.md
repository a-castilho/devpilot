## Análise
O travamento persistia mesmo após reduzir o peso do Project Builder porque o problema não estava apenas no formulário. O runtime `viewport-adaptive-v15.js` escutava `visualViewport.scroll` e `visualViewport.resize` e, a cada gesto no celular, reescrevia classes, `data-*` e CSS variables no `<html>`. No Chrome/Brave Android a barra de endereço altera o `visualViewport` durante a rolagem, provocando recálculo de estilo/layout global em uma tela longa como o cadastro.

## Correção V38
- remove o listener de `visualViewport.scroll`;
- ignora `resize` mobile quando apenas a altura mudou e a largura permaneceu igual;
- cria assinatura estrutural para não reaplicar viewport quando nada relevante mudou;
- evita reescrever classes, CSS vars e datasets quando o valor já é o mesmo;
- mantém atualização completa para mudança real de largura/orientação e desktop;
- mantém o fluxo de Novo projeto e Nova execução inalterado.

## Verificação
- `node --check app/static/viewport-adaptive-v15.js` validado antes do commit;
- teste de regressão garante ausência do listener de scroll e atualizações idempotentes.
