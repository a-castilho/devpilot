## Descrição e evidências da PR

## DevPilot 1.1.0

Esta PR prepara a nova versão **1.1.0**, consolidando a recuperação do incidente de travamento e transformando as correções em padrões permanentes de confiabilidade.

## Versão
- `app.version.__version__ = 1.1.0` é a fonte única;
- `pyproject.toml` usa versão dinâmica a partir de `app.version.__version__`;
- FastAPI e `/health` continuam usando a mesma fonte;
- `tests/test_release_version.py` impede nova divergência de versão.

## Confiabilidade implementada
- padrão obrigatório em `AGENTS.md` e `docs/ENGINEERING_STANDARD.md`;
- gate rápido `DevPilot policy` antes de `DevPilot quality`;
- boot pré-auth somente com `acs-loader.js` + `auth-ui.js`;
- core autenticado somente com `app.js` + `feature-loader.js`;
- features opcionais exclusivamente sob demanda;
- bloqueio de loaders ocultos/segunda onda automática/novos MutationObservers globais;
- runtime local identifica `/health`, PID, porta e commit e possui rollback seguro.

## Correções adicionais exigidas pela revisão sênior
- o gate de frontend deve detectar loaders dinâmicos mesmo quando formatados em múltiplas linhas;
- o runtime deve falhar fechado quando não houver mecanismo confiável para inspecionar o listener da porta;
- se o shutdown exceder o limite após avanço de HEAD, a revisão anterior deve ser restaurada antes de encerrar a operação.

## GitHub Actions
A organização consumiu os minutos hospedados incluídos. Os workflows críticos usam `vars.DEVPILOT_RUNNER || 'ubuntu-latest'` e existe `scripts/setup-github-self-hosted-runner.sh` para ativar runner próprio sem remover os gates.

**A tag/release `v1.1.0` não deve ser publicada antes de `DevPilot policy` e `DevPilot quality` verdes e do merge desta PR na `main`.**
