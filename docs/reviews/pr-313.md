## Descrição e evidências da PR

Causa raiz: o handler legado de `[data-view]` chama `showView('projects')` antes do roteador em `document`, e `showView` dispara `loadProjects()` com `/ui/projects?limit=50`. No celular isso acontece antes de `mobile-project-card-compact.js` instalar o guard de modo leve, causando renderização/carga pesada e travamento.

Correção:
- `page-navigation-v26.js` intercepta `showView('projects')` em viewport <= 900px antes do `nativeShowView`;
- mostra a view imediatamente, preservando o layout existente;
- carrega a feature `projects` primeiro;
- só então chama `window.loadProjects()`, já envelopado pelo guard mobile que limita a 12 projetos;
- desktop continua usando o fluxo atual sem alteração visual.

Inclui teste de regressão para garantir a ordem: feature mobile antes de `loadProjects()` e interceptação antes do `nativeShowView`.
