## Descrição e evidências da PR

## Objetivo
Completar o primeiro gap da reação automática da esteira sem criar pipeline paralelo.

## O que já existia e foi reutilizado
- workflow `CI` com `DevPilot policy` e `DevPilot full quality`;
- gate oficial `bash scripts/test-all.sh`;
- artifacts de falha do CI;
- API real `/api/projects` e `/api/tasks`;
- EmbeddedWorker/Task workflow existente;
- policy de aprovação para ações sensíveis.

## Implementação
- novo workflow `DevPilot CI failure reaction`, disparado por `workflow_run` somente quando o workflow `CI` termina em `failure`;
- bridge stdlib `scripts/ci-failure-to-task.py`;
- resolve o projeto pelo repositório GitHub, sem ID hard-coded;
- deduplica por `[github-ci-run:<run_id>]` para não criar tasks repetidas;
- cria Task real via `/api/tasks`, prioridade 90 e source `api`;
- a Task manda recuperar o estado atual, diagnosticar causa raiz, aplicar somente correção local e executar `bash scripts/test-all.sh`;
- explicitamente não publica alterações nem integra `main`, preservando approval para push/merge;
- token fica somente em `secrets.DEVPILOT_AUTOMATION_TOKEN`; URL em `vars.DEVPILOT_AUTOMATION_URL`.

## Configuração necessária no GitHub
- Repository variable: `DEVPILOT_AUTOMATION_URL`
- Repository secret: `DEVPILOT_AUTOMATION_TOKEN`

## Testes
`tests/test_ci_failure_task_bridge.py` protege trigger, idempotência, uso das APIs reais e ausência de bypass das ações sensíveis.
