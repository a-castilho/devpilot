## Descrição e evidências da PR

## Problema
Execuções de projeto ainda podiam falhar em `git clone` com `terminal prompts disabled` mesmo quando a credencial GitHub já estava salva no painel administrativo.

A causa raiz era dupla:
- o resolver considerava apenas `provider=github`, enquanto o painel Cloud salva GitHub como `cloud:github` (e existe legado `cloud-github`);
- alguns caminhos do executor ainda chamavam o checkout antigo, que podia executar `git clone` sem o preflight autenticado.

## Correção
- aceita `github`, `cloud:github` e `cloud-github` como fontes GitHub do mesmo workspace;
- extrai o token do formato legado JSON sem expor segredo;
- valida cada credencial contra o repositório exato via `git ls-remote`;
- força o checkout do executor pelo caminho autenticado com preflight;
- mantém isolamento por workspace e não envia o token ao frontend.
