## Descrição e evidências da PR

## Problema observado

Após a instalação, `devpilot-linux-agent.service` entra em auto-restart com `status=1/FAILURE` ao executar `.venv/bin/python -m app.linux_agent`.

O socket do Agent estava sendo criado diretamente em `./runtime/linux-agent.sock`. Esse diretório também é manipulado por containers do DevPilot e pode ficar pertencendo a root, impedindo o serviço `systemd --user` de criar o Unix socket.

## Correção

- move o socket para `runtime/linux-agent/agent.sock`;
- usa um diretório dedicado ao Agent;
- repara propriedade do diretório via Docker quando `runtime` tiver sido criado como root;
- não torna todo `runtime` world-writable;
- atualiza o caminho visto pelo container app;
- para crash-loop anterior antes da reinstalação;
- regrava `linux-agent.env` em reinstalações para não manter caminho antigo;
- valida import do Agent antes do systemd;
- executa health-check real pelo Unix socket após iniciar;
- em falha, imprime `systemctl status` e os últimos 60 logs do journal e retorna erro em vez de declarar instalação concluída.

O CI já contém `bash -n scripts/install-linux-agent.sh` além da suíte completa do DevPilot.
