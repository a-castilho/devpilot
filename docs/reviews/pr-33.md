## Corrige
Fecha o risco da issue #15: `DEVPILOT_BOOTSTRAP_TOKEN` deixa de funcionar como sessão `SUPER_ADMIN` permanente.

## Mudanças
- `current_principal()` aceita somente access tokens de usuário;
- bootstrap fica restrito a `POST /api/auth/bootstrap` via `require_bootstrap_access`;
- UI remove o fluxo de “Acesso técnico por token”;
- primeiro acesso continua usando o bootstrap para criar o primeiro `SUPER_ADMIN`;
- testes garantem que bootstrap é aceito no setup e rejeitado como sessão normal;
- README documenta rotação/remoção do segredo após configuração inicial.

## Segurança
Depois que o primeiro usuário existir, conhecer o bootstrap token sozinho não permite mais autenticar uma sessão administrativa normal.
