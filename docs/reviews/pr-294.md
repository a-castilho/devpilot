## Descrição e evidências da PR

Corrige o travamento persistente ao entrar no Modo Jogo reduzindo o auto-boot real, sem desfazer v63/v64.

- o bootstrap ainda carregava 8 módulos opcionais em sequência logo após o primeiro paint;
- `final-delivery-summary.js` e `build-game-url-bonus.js` possuem observers `subtree:true` e não são necessários para iniciar uma rodada;
- `pipeline-v2-compat.js` ainda envolve `window.api`, embora o runtime standalone atual já normalize as tarefas;
- `start-round-mobile.js` ficou redundante porque o quick-start já implementa a entrada em um clique.

Correção v65:
- mantém apenas 3 módulos imediatamente pós-paint: `action-runtime`, `task-payload-guard`, `objective-controls`;
- `delivery-gate` passa para grupo background e só é carregado após delay/idle quando existe missão;
- `build-game-url-bonus` e `final-delivery-summary` só carregam quando `.build-game-victory` realmente existe;
- `start-round-mobile.js` e `pipeline-v2-compat.js` saem do auto-boot;
- carregamento de assets é deduplicado em memória;
- mantém core-first com somente runtime + build-game + bootstrap no caminho crítico;
- preserva v63: POST direto, dedupe in-flight, recovery e yield mobile;
- preserva v64: gate sem wrapper, 7 fases, controles sem MutationObserver;
- cache atualizado para `release-1.2.0-game-entry-minimal-v65-20260902`;
- contratos antigos atualizados para exigir o perfil mínimo.

Resultado esperado: entrar no jogo permanece responsivo; módulos de verificação e entrega não competem com a primeira interação.
