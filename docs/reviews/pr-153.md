## Descrição e evidências da PR

## Objetivo
Separar o Modo Jogo do ciclo de vida do dashboard para eliminar a classe de travamentos causada por lazy loading, observers/listeners compartilhados e reentrada no mesmo documento.

## Implementação
- novo documento isolado em `/game/index.html`;
- bootstrap próprio do jogo sem `feature-loader.js` e sem sidebar do dashboard;
- saída do jogo faz navegação completa para `/`;
- placeholder `Modo Jogo` do dashboard navega para o runtime isolado em vez de carregar `game-shell.js`/`build-game.js` dentro do dashboard;
- entrada visual do jogo usa a mesma URL isolada;
- regressões garantem que o jogo não volte a depender do feature-loader do dashboard.

## Compatibilidade
O backend, token atual, APIs e estado persistido do jogo continuam compartilhados. O motor `build-game.js` é reutilizado; não há novo backend, banco ou login.
