## Descrição e evidências da PR

## Problema
Falhas recuperáveis, especialmente `401 Unauthorized` do Codex/OpenAI, eram escaladas imediatamente para autorização humana. Isso contrariava a regra operacional do DevPilot: executar correções e failovers automáticos antes de solicitar qualquer ação externa.

## Implementação
- adiciona failover automático entre credenciais OpenAI ativas já cadastradas no cofre;
- passa a injetar a credencial OpenAI selecionada apenas no processo Codex do projeto, sem alterar autenticação global do worker;
- evita repetir a mesma credencial durante o mesmo ciclo de recuperação;
- só marca `requires_authorization=true` para Codex depois de esgotar as alternativas automáticas;
- adiciona retry limitado para indisponibilidade transitória de banco antes da recuperação de causa raiz;
- mantém recuperação automática para falhas sem estratégia direta, sem pedir ação humana por padrão;
- adiciona testes da política de recuperação automática e do isolamento da credencial por projeto.

## Fluxo esperado para o caso observado
`401 Codex -> diagnosticar -> selecionar credencial OpenAI alternativa do cofre -> repetir a mesma tarefa -> tentar próxima credencial se necessário -> somente após esgotar alternativas pedir nova autorização humana`.
