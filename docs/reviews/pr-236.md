## Problemas corrigidos

1. A tela de Tarefas mostrava `RUNNER ESTADO DESCONHECIDO` mesmo com o worker do DevPilot executando a tarefa. O card usava o status do self-hosted GitHub Actions Runner como se fosse o worker de tarefas.
2. Uma nova rodada do Jogo V2 ainda podia herdar automaticamente `Project.description` como objetivo, apesar do contrato exigir que o usuário escreva a entrega da rodada.

## Correção

- separa explicitamente **Worker de tarefas** e **GitHub Actions Runner** na observabilidade;
- usa estados persistidos de tarefas/runs para mostrar `Worker de tarefas ativo`, `Fila aguardando worker` ou `Worker sem execução ativa`;
- mantém o GitHub Actions Runner como infraestrutura separada e restrita ao Super Admin;
- quando `systemd --user` não é visível de dentro do runtime, a API deixa claro que isso não representa o estado do worker de tarefas;
- remove o fallback de `Project.description` no objetivo do Jogo V2;
- nova rodada começa sem objetivo até o usuário escrever uma entrega explícita;
- partidas já iniciadas preservam o objetivo histórico imutável.

## Testes de regressão

- objetivo do jogo não pode mais vir da descrição do projeto;
- observabilidade exige separação textual e funcional entre task worker e GitHub Actions;
- status `unknown` do runner de CI não pode afirmar que o worker de tarefas está indisponível.
