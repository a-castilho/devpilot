## Descrição e evidências da PR

## Problema
Na tela **Novo projeto**, usuários autorizados pelo fluxo automático recebem apenas `Não foi possível criar o projeto. A administração foi notificada.` quando o provisionamento do GitHub falha. O backend só preservava o projeto como `repository_pending` para `SUPER_ADMIN`, apesar de OWNER/ADMIN também poderem usar `/api/projects/provision`.

## Correção
- preserva o cadastro do projeto para qualquer perfil autorizado ao fluxo automático quando o GitHub estiver indisponível, sem credencial válida ou recusar o provisionamento;
- mantém o erro detalhado somente na auditoria, sem expor credenciais/configuração a usuários comuns;
- retorna o projeto com `repository_pending=true` e `repository_mode=deferred`, permitindo conectar o Git depois;
- adiciona regressão cobrindo OWNER no fallback automático.

## Cenário reproduzido
Projeto `André Tonal` / slug `andre-tonal` na tela Novo projeto.

## Segurança
A política de privacidade do diagnóstico não foi removida: usuários comuns continuam sem receber detalhes de PAT/GitHub. A mudança evita apenas perda/bloqueio do cadastro quando o provedor externo falha.
