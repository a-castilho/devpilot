## Descrição e evidências da PR

Corrige o travamento percebido ao entrar no Modo Jogo no próprio caminho crítico do motor.

Causa confirmada no código:
- `window.loadBuildGame()` executa `await ensureProjects()`;
- depois executa `await api('/tasks?...')`;
- somente então chama `render(...)`;
- portanto duas consultas de rede ainda bloqueavam o primeiro shell real, mesmo após v65/v66.

Correção v67:
- adiciona um bridge inline entre `build-game.js` e `game-bootstrap.js`;
- renderiza imediatamente `.build-game-shell` sem depender de rede;
- dispara a hidratação real do motor em background;
- a primeira chamada feita pelo bootstrap retorna imediatamente, sem aguardar projetos/histórico;
- chamadas seguintes entram na mesma Promise de hidratação, sem duplicar rede;
- quando o motor real monta `#build-game-project`, emite `devpilot:game:rendered` para os controles existentes;
- se os dados falharem, mantém uma tela utilizável com botão `Tentar novamente`;
- após 3,5s troca apenas a mensagem para indicar servidor lento, sem polling/loop;
- preserva os três scripts externos críticos e todos os contratos de cache v65/v66.

Teste novo `test_game_nonblocking_entry_v67.py` garante ordem do bridge, first paint antes da hidratação, bootstrap não bloqueante, retry e ausência de loop/MutationObserver.
