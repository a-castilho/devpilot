## Descrição e evidências da PR

## Problema
A tela de Organizações ficava em `GITHUB · FAILED` quando o Fine-grained PAT expirava ou era revogado. A API já permitia substituir a credencial criptografada, mas a interface não oferecia um caminho para recuperar a organização existente; o formulário de nova organização também não expunha o campo de token na versão atual.

## Correção
- carrega o fluxo de credenciais de Organizações somente após navegação explícita, via `feature-loader.js`;
- adiciona campo protegido de Fine-grained PAT ao cadastro de organização sem colocar credenciais no boot automático;
- adiciona ação `Atualizar credencial GitHub` para substituir o token de uma organização existente;
- exige confirmação de `Resource owner = a-castilho` no caso gerenciado;
- reutiliza `PATCH /organizations/{id}`, que já grava no vault criptografado e audita a configuração;
- limpa o token do DOM após tentativa e dispara sincronização para validar a nova credencial;
- adiciona testes de regressão para carregamento sob demanda, proteção do segredo e revalidação.

## Segurança / padrão do projeto
Nenhum token é persistido no frontend, exibido pela API ou logado. O módulo não cria loaders, não usa `MutationObserver` e é carregado exclusivamente pelo `feature-loader.js`, preservando o boot mínimo definido em `AGENTS.md` e `docs/ENGINEERING_STANDARD.md`.
