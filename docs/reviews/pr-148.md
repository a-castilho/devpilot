## Descrição e evidências da PR

## Problema
O bootstrap do self-hosted runner confiava principalmente no `.runner.pid`. Quando o PID file ficava ausente/obsoleto enquanto o runner registrado continuava online, uma nova execução podia iniciar outro `Runner.Listener` com o mesmo nome e provocar `SessionConflictException`.

## Correção
- consulta o estado autoritativo do runner no GitHub antes de iniciar nova sessão;
- se o runner já estiver `online` (inclusive `busy`), encerra com sucesso sem iniciar outro listener;
- recupera um `Runner.Listener` local já existente mesmo se o PID file estiver perdido;
- só inicia `run.sh` quando não há sessão remota online nem listener local vivo;
- adiciona teste de regressão para os dois caminhos.

## Segurança operacional
Não interrompe runner `busy`, não remove registro e não enfraquece `DevPilot policy`/`DevPilot full quality`.
