## Descrição e evidências da PR

## Evidência
A captura do Android mostra que o cadastro abre, mas trava/janka durante o uso interno. Também mostra os checkboxes de **Fluxo de entrega** ocupando quase toda a largura, sinal de herança indevida de `.builder-card input { width:100% }`.

## Causa raiz
- overrides responsivos posteriores transformavam `.choice-strip` em grid no mobile, expandindo todas as opções de todos os grupos no fluxo vertical;
- isso faz o navegador calcular/pintar dezenas de cards simultaneamente enquanto o usuário rola o cadastro;
- checkboxes herdavam a regra genérica de inputs com largura total, aumentando muito a área de layout e produzindo o visual da captura;
- o formulário precisa ter um único scroll vertical; as escolhas técnicas devem continuar como carrossel horizontal, como o próprio texto da UI orienta.

## Correção V35
- restaura `.choice-strip` como carrossel horizontal no cadastro em até 900px;
- evita expansão vertical de todos os cards;
- aplica `content-visibility:auto`/containment aos grupos fora da viewport;
- normaliza checkboxes para 22x22px e labels de 44px de altura mínima;
- garante scroll vertical nativo no `new-project-view` e remove nested overflow;
- não altera o desktop nem a estrutura HTML do cadastro.

Inclui testes estruturais para o carrossel, checkbox e otimização de conteúdo fora da viewport.
