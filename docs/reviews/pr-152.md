## Objetivo
Automatizar a recuperação de PRs vermelhas sem enfraquecer os gates e sem automatizar merge/deploy.

## Fluxo
- observa o término do workflow `CI`;
- atua somente em `failure`/`timed_out`, branch não-main, PR aberta e branch do mesmo repositório;
- usa o runner self-hosted configurado e Codex para diagnosticar o log do CI;
- permite no máximo 3 commits `fix(ci): auto-repair ...` por branch;
- bloqueia execução se o run ficou obsoleto porque a branch avançou;
- impede alteração da política, AGENTS, Engineering Standard, `ci.yml`, workflow de auto-repair e scripts dos gates;
- rejeita segredo detectável no diff;
- executa `scripts/test-all.sh` com browser E2E antes de qualquer push;
- faz push normal, sem force, somente na própria branch da PR;
- dispara explicitamente novo `ci.yml` para fechar o loop mesmo quando o push usa `GITHUB_TOKEN`;
- gera artefato JSON auditável por tentativa.

## Governança
A autorização permanente é versionada em `.devpilot/pr-auto-repair.json` na `main`. A política exige `allow_merge=false`, mesma origem, PR aberta, validação completa e máximo rígido de 3 tentativas. PRs não podem auto-habilitar nem alterar essa política durante uma correção porque o controlador lê a política de `origin/main` e protege esse arquivo.
