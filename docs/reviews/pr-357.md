## Descrição e evidências da PR

## Problema
Na tela de Execuções, tarefas antigas que continuam com status `queued` aparecem como **Na fila**, mas não exibem ação **Excluir**. O backend também rejeitava qualquer `queued` como tarefa ativa, mesmo quando nenhum worker a havia reivindicado.

## Correção
- permite excluir `queued` somente quando não existe claim ativo no runtime;
- usa compare-and-set `queued -> failed` como fencing antes da exclusão, impedindo corrida com o worker;
- se o worker reivindicar a tarefa primeiro, a API responde `409` e não remove dados;
- remove runtime e eventos de aprendizado órfãos associados à tarefa excluída;
- adiciona **Excluir** aos cards para `queued`, `awaiting_approval`, `completed`, `failed` e `blocked`, apenas para SUPER_ADMIN;
- mantém confirmação explícita e recarrega dashboard/lista após a exclusão;
- `planning`, `running` e `review` continuam não excluíveis.
