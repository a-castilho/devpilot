## Descrição e evidências da PR

## Objetivo
Preparar uma homologação funcional do DevPilot usando Neon para persistência, Render para o backend e Vercel para o frontend.

## Implementação
- troca o `render.yaml` de SQLite temporário para `DEVPILOT_DATABASE_URL` seguro, preenchido externamente com a branch Neon de homologação;
- adiciona `DEVPILOT_AUTH_SECRET`, diretórios temporários explícitos e demais variáveis necessárias no Render;
- adiciona `DEVPILOT_EMBEDDED_WORKER`, desligado por padrão e ligado somente na homologação, para consumir a fila sem contratar background worker pago no Render;
- adiciona ciclo de vida seguro do worker embutido ao FastAPI;
- adiciona testes do worker embutido;
- adiciona build estático da UI para Vercel preservando os scripts que o FastAPI injeta dinamicamente;
- adiciona `vercel.json` com proxy `/api` configurável por `DEVPILOT_BACKEND_URL`.

## Segurança
- execução automática permanece `false` na homologação;
- nenhum segredo é versionado;
- URL do Neon permanece variável `sync: false` no Render;
- backend da Vercel é configurado por variável de ambiente, sem credencial ou domínio sensível no código.

## Arquitetura
O worker embutido é específico para homologação single-instance. Produção continua compatível com worker dedicado.
