## Descrição e evidências da PR

## Problema
No runtime local o DevPilot pode usar SQLite no core e PostgreSQL/pgvector separado para RAG. A configuração administrativa do RAG estava sendo salva e carregada pelo `core_engine`; em SQLite, `settings_store` não persiste nada. Por isso o botão podia mostrar RAG ativo momentaneamente e voltar para `disabled` após reload.

## Correção
- carrega `rag_runtime_settings` pelo `get_rag_engine()`;
- salva alterações administrativas pelo mesmo storage vetorial;
- preserva o banco principal do DevPilot separado;
- atualiza o contrato de testes de storage separado.

## Resultado esperado
Ativar/desativar RAG e demais opções pelo painel persiste corretamente mesmo com core SQLite + RAG PostgreSQL/pgvector.
