## Descrição e evidências da PR

## Objetivo
Corrigir riscos de fronteira de credencial nas operações Git e impedir falso negativo quando a credencial GitHub já existe no workspace, mas um projeto legado/assíncrono ainda está sem `organization_id`.

## Mudanças
- revalida `project.repository_url` imediatamente antes de operações Git com rede;
- `Organization` e `ProviderCredential` precisam pertencer ao mesmo workspace do projeto;
- PAT de organização GitHub.com só é anexado quando o host validado é `github.com`;
- troca `http.extraHeader` global por `http.https://github.com/.extraHeader`;
- checkout existente tem o `origin` lido, normalizado e comparado com a URL persistida; divergência falha fechado, sem reescrever o remote;
- a auto-recuperação pode resolver `organization_id` ausente somente pelo owner da URL validada `github.com/<owner>/<repo>` e somente dentro do mesmo workspace;
- o vínculo projeto-organização só é reparado depois que uma credencial ativa do mesmo workspace comprova acesso com `git ls-remote`;
- se o projeto já possui `organization_id`, o `external_login` da organização precisa corresponder ao owner do repositório; divergência interrompe o fluxo sem transmitir credencial;
- não existe fallback global nem uso de organização/credencial de outro workspace;
- URL inválida ou host diferente interrompe a recuperação sem transmitir token;
- adiciona regressões para cross-workspace, host custom, escopo do header, origin adulterado, credencial já cadastrada com vínculo ausente e owner incompatível;
- documenta a fronteira em `docs/SECURITY_GIT_CREDENTIAL_BOUNDARY.md`.

## Segurança
A estratégia permanece fail-closed. A inferência da organização só ocorre quando o owner do repositório identifica inequivocamente uma organização GitHub do mesmo workspace. Nenhum token novo é criado, nenhuma autorização é inventada e nenhuma organização explícita é substituída automaticamente.

## Compatibilidade
Sem migration, sem mudança de payload/API e sem novo segredo. Projetos existentes sem `organization_id` podem ser reparados de forma aditiva pela auto-recuperação após validação real da credencial já cadastrada.
