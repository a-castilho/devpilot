## Descrição e evidências da PR

## Objetivo
Corrigir um risco de fronteira de credencial nas operações Git. O executor e a auto-recuperação confiavam no `repository_url` persistido e configuravam o PAT GitHub como `http.extraHeader` global; um checkout local também podia ter `origin` alterado independentemente do banco.

## Mudanças
- revalida `project.repository_url` imediatamente antes de operações Git com rede;
- `Organization` e `ProviderCredential` precisam pertencer ao mesmo workspace do projeto;
- PAT de organização GitHub.com só é anexado quando o host validado é `github.com`;
- troca `http.extraHeader` global por `http.https://github.com/.extraHeader`;
- realinha `origin` à URL persistida/validada antes de `git fetch` em checkout existente;
- aplica as mesmas regras ao `git ls-remote` da auto-recuperação;
- URL inválida ou host diferente interrompe a recuperação sem transmitir token;
- adiciona regressões para cross-workspace, host custom, escopo do header, origin adulterado e recovery;
- liga `recovery.py` e os testes novos aos gates críticos `tasks_worker` e `github`;
- documenta a fronteira em `docs/SECURITY_GIT_CREDENTIAL_BOUNDARY.md`.

## Segurança
A lista `DEVPILOT_ALLOWED_GIT_HOSTS` continua sendo respeitada. A mudança não remove hosts autorizados pelo operador; apenas impede que um PAT gerenciado para GitHub.com seja enviado automaticamente a outro host. Dados legados também passam pela mesma validação de URL na hora da execução.

## Compatibilidade
Sem migration, sem mudança de payload/API e sem novo segredo. Repositórios públicos em hosts adicionais continuam acessíveis, mas sem herdar PAT de organização GitHub.com.
